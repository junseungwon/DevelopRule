# 항상 적용되는 기본 규칙 (Always Rules)

> 모든 작업 시작 시 항상 이 파일을 먼저 읽고 적용하는 규칙입니다.

---

## 📋 Core Rules

### 0. 모든 작업은 CEO 에이전트를 통해 시작한다
사용자로부터 작업 요청이 들어오면 **반드시 CEO 에이전트를 먼저 실행**한다.
- CEO 에이전트 정의: `C:\DevelopRule\agents\management\ceo.md`
- CEO가 요청을 분석하여 CTO / 인사계 등 적절한 하위 에이전트에 위임
- 단순 질문·조회성 요청은 예외 (직접 응답 가능)

### 0-1. 개발·기술 질문은 CEO → CTO 경로로 처리한다
아래 트리거 키워드가 포함된 요청은 CEO 에이전트를 스폰한 후 CEO가 **CTO 에이전트를 스폰**하여 처리를 위임한다.
- CTO 에이전트 정의: `C:\DevelopRule\agents\management\cto.md`

**트리거 키워드 (하나라도 해당하면 CTO 위임)**
| 분류 | 키워드 예시 |
|------|-----------|
| 구현·개발 | 구현, 개발, 만들어줘, 추가해줘, 작성해줘, implement, 기능 만들어 |
| 설계·아키텍처 | 설계, 아키텍처, 구조, 클래스 다이어그램, 의존성, 패턴, design |
| 코드 품질 | 리뷰, 점검, 리팩터링, 버그, 개선, review, refactor |
| Unity·C# 기술 | Unity, C#, MonoBehaviour, ScriptableObject, Animator, Shader |
| 분석 | 분석, 조사, 왜 이렇게, 어떻게 동작, 성능, analyze |

**예외 (직접 응답)**: 단순 파일 위치 확인, 단순 조회, 이미 완료된 내용 재확인

---

### 1. 사용한 에이전트 및 적용한 규칙을 표시한다
각 작업 완료 후 다음 정보를 대화창에 기록하세요:
- **사용한 에이전트**: 어떤 에이전트를 사용했는지
- **적용한 규칙**: 어떤 규칙을 적용했는지

```
## ✅ 작업 완료

**작업**: [작업 설명]
**사용 에이전트**: [에이전트 이름]
**적용 규칙**: [규칙명]
```

---

### 2. 사용자가 에이전트를 사용하라고 하면 사용할 에이전트를 배치도를 사용자에게 알려줘야한다
에이전트 사용 전에:
- 사용할 에이전트들의 역할과 관계를 **배치도(Diagram)**로 시각화
- 각 에이전트의 책임 범위 명시
- 워크플로우 순서 제시
- 사용자 승인 후 진행

---

### 3. 사용자가 자동승인을 요청하면 권한요청을 보내지말고 진행을 한다
- 사용자가 "자동승인", "권한 요청 없이 진행" 등을 요청하면:
  - 권한 요청 다이얼로그 표시 금지
  - 필요한 작업 즉시 진행
  - 진행 상황을 대화창에 보고

---

### 4. 사용자가 에이전트 변경을 요청하면 해당 부분에 사용 가능한 에이전트를 추천 리스트로 작성해서 제공한다
에이전트 변경 요청 시:
- 현재 사용 중인 에이전트 명시
- 변경 가능한 에이전트 **추천 리스트** 제시
  - 각 에이전트별 특징과 장단점
  - 작업에 맞는 최적의 에이전트 하이라이트
- 사용자 선택 후 배치도 다시 제시
