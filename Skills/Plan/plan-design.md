| 속성 | 값 |
|------|-----|
| 스킬명 | plan-design |
| 역할 | 게임 기획·컨셉·GDD(Game Design Document) 설계 절차 정의 |
| 사용 에이전트 | plan-designer |
| 참조 규칙 | `C:\DevelopRule\Rule\Always\Always.md` |

## 설계 범위

| 설계 유형 | 내용 |
|----------|------|
| 코어 루프 | 게임의 핵심 플레이 사이클 (Action → Feedback → Reward) |
| 메카닉 설계 | 개별 게임플레이 메카닉 정의 및 규칙 명세 |
| 레벨 설계 원칙 | 난이도 곡선, 튜토리얼 흐름, 레벨 구조 원칙 |
| 캐릭터 설계 | 플레이어블 캐릭터 능력·스탯·성장 구조 |
| 컨셉 아트 방향 | 아트 스타일 가이드, 분위기, 레퍼런스 무드보드 |
| GDD 구조 | 전체 기획서 목차·섹션 설계 |

---

## 설계 절차

### 1단계 — 컨셉 수립

- 게임 한 줄 설명 (Elevator Pitch)
- 타겟 유저, 플랫폼, 장르 명시
- 핵심 재미 요소 (Core Fun) 3개 이내로 정의
- 레퍼런스 게임 2~3개 선정 (plan-researcher 조사 결과 활용)

### 2단계 — 코어 루프 설계

```
[플레이어 행동] → [즉각 피드백] → [보상/진행] → [다음 행동 동기]
```

- 각 단계의 구체적 내용 명시
- 루프 사이클 시간 (초 단위) 정의
- 루프 중단 조건(실패 상태) 정의

### 3단계 — 메카닉 명세

각 메카닉에 대해:
```markdown
### [메카닉명]
- **목적**: 이 메카닉이 제공하는 재미/목표
- **규칙**: 동작 규칙 (불변식 포함)
- **입력**: 플레이어 입력 또는 시스템 트리거
- **출력**: 결과 상태 변화
- **엣지 케이스**: 예외 처리 시나리오
```

### 4단계 — GDD 초안 작성

GDD 필수 섹션:
```markdown
# [게임명] GDD v{버전}

## 1. 게임 개요
## 2. 타겟 유저
## 3. 코어 루프
## 4. 메카닉 목록
## 5. 레벨 설계 원칙
## 6. 캐릭터 설계
## 7. 아트 방향성
## 8. 사운드 방향성
## 9. UI/UX 개요
## 10. 기술 요구사항 (plan-spec-writer 위임)
```

## 설계 원칙

- 재미(fun)를 수치나 메카닉으로 반드시 근거 제시
- "대충"·"적당히" 등 모호한 표현 금지 — 수치 또는 조건으로 대체
- 설계 의존 관계(선행 메카닉 → 후행 메카닉) 명시
- 미결 사항(TBD)은 별도 섹션에 모아서 표시
