# 문서화 스킬

## 스킬 정의

| 속성 | 값 |
|------|-----|
| 스킬명 | documentation |
| 역할 | 기술 문서 작성·정리 절차 및 형식 기준 정의 |
| 사용 에이전트 | documenter, unity-documenter |
| 참조 규칙 | `C:\DevelopRule\Rule\Always\Always.md` |

---

## 문서 작성 원칙

1. 모든 문서는 한국어로 작성한다 (사용자가 명시적으로 다른 언어를 요청한 경우 제외)
2. 독자 관점에서 작성 (배경 지식 수준 고려)
3. 목차 → 개요 → 상세 순서로 구성
4. 이모지 사용 금지 (사용자 명시 요청 시 제외)
5. 문서 범위를 벗어난 코드 수정 금지

---

## 문서 유형별 형식

### 코드 리뷰 결과 문서

저장 경로: `docs/code-review/{YYYY-MM-DD}-{프로젝트}-code-review.md`

```markdown
# 코드 리뷰 결과 — {YYYY-MM-DD}

## 개요
{리뷰 범위, 참여 에이전트, 검증 규칙}

## 주요 발견사항
{심각도별 요약}

## 항목별 수정 가이드

### {파일명:라인} — {항목명}
현재:
{현재 코드 또는 패턴}

목표:
{개선 후 코드 또는 패턴}

수정 절차:
- [ ] {절차 1}
- [ ] {절차 2}

참고 규칙: {UNITY-XXX}

## 검증 규칙 인용
{UNITY-003, UNITY-021, ...}
```

### 설계 문서

저장 경로: `docs/design/{YYYY-MM-DD}-{기능명}-design.md`

```markdown
# {기능명} 설계 문서

## 개요
{설계 목적 및 범위}

## 구조 설계
{클래스 다이어그램 또는 텍스트 다이어그램}

## 의존성
{의존성 방향 그래프}

## 인터페이스 정의
{시그니처만 포함}

## 적용 규칙
{UNITY-XXX, UCA-XXX}
```

### API·모듈 문서

저장 경로: `docs/api/{모듈명}.md`

```markdown
# {모듈명}

## 역할
{한 줄 설명}

## 공개 API
| 메서드명 | 반환 타입 | 파라미터 | 설명 |
|---------|---------|---------|------|

## 사용 예시
{코드 블록}

## 주의사항
{알려진 제약·한계}
```

## Unity 전용 문서 기준 (unity-documenter)

Unity 프로젝트 문서 작성 시 추가 규칙:

- 씬·Prefab 경로는 `Assets/` 기준 상대 경로로 명시
- 컴포넌트 참조는 `{GameObjectName}/{ComponentName}` 형식
- Animator 파라미터는 타입과 기본값 함께 명시
- ScriptableObject 경로는 `Assets/88_ScriptableObjects/` 기준

## 에러 핸들링

| 상황 | 처리 |
|------|------|
| 정보 부족 | 빈 섹션 표시 후 추가 정보 요청 |
| 기존 문서 충돌 | 차이점 명시 후 병합 방향 제안 |
| 저장 경로 미지정 | 현재 작업 디렉토리의 `docs/` 하위에 저장 |
