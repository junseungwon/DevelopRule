# 폴더 구조 규칙

## 1. 네이밍 컨벤션

모든 폴더는 **`{숫자}_{PascalCaseName}`** 형식을 따른다.

- 숫자는 **두 자리 정수** (`00`, `01`, ... `09`, `10` ...)
- 이름은 **PascalCase** (영문, 공백 없음)
- 예: `00_ProjectSettings`, `02_Scripts`, `99_ExternalAssets`

### 예약 접두사

| 범위 | 용도 |
|------|------|
| `00~09` | 프로젝트 핵심 / 최상위 우선순위 |
| `10~79` | 일반 기능 폴더 (순서대로 배치) |
| `88_` | 특수 목적 (ScriptableObjects, 공유 리소스 등) |
| `99_` | 외부 에셋 / 레거시 / 아카이브 |

## 2. Unity Assets 폴더 구조 예시

```
Assets/

├── 02_Scripts/
```

## 3. Docs 폴더 — 5단계 법칙

프로젝트 루트의 `Docs/` 폴더는 문서화 생명주기 5단계로 구성한다.

```
Docs/
├── 00_Planning/      — 기획, 아이디어, 요구사항 정의
├── 01_Design/        — 시스템 설계, 아키텍처, UML
├── 02_Specification/ — 기능 스펙, API 명세, 데이터 정의
├── 03_Review/        — 코드 리뷰, 회의록, QA 리포트
└── 99_Archive/       — 폐기된 문서, 구버전 스펙 보관
```

### 단계별 역할

| 단계 | 폴더 | 저장 문서 예시 |
|------|------|---------------|
| 1 | `00_Planning` | 기획서, 마일스톤, 유저 스토리 |
| 2 | `01_Design` | 아키텍처 다이어그램, 시스템 설계서 |
| 3 | `02_Specification` | 기능 명세서, 데이터 테이블, API 문서 |
| 4 | `03_Review` | 리뷰 피드백, 회의록, 버그 리포트 |
| 5 | `99_Archive` | 더 이상 유효하지 않은 구버전 문서 |

---

## 4. 적용 원칙

- 새 폴더 생성 시 반드시 위 컨벤션에 맞는 번호를 배정한다.
- 번호 중간 삽입이 필요하면 기존 번호를 유지하고 소수점 없이 새 번호를 부여한다 (예: `03_`, `04_` 사이에 넣을 경우 `035_` 대신 번호 범위를 재조정).
- `.gitkeep` 파일로 빈 폴더를 Git에 추적한다.
- `99_Archive`는 삭제 대신 이동의 종착지로 사용한다.
