# 프롬프트 엔지니어링

10. **구체적인 위치 지목:** "버그 고쳐줘" 대신 "InteractionController.cs의 TryGrab 함수 오류"라고 명시합니다.
11. **출력 형식 지정:** 응답받고 싶은 포맷(JSON, Markdown 등)을 처음부터 확정 지어줍니다.
12. **Negative Prompt 사용:** "기존 주석은 삭제하지 마", "다른 함수는 건드리지 마" 등 하지 말아야 할 것을 명시합니다.
13. **변경분만 출력 유도:** 전체 코드를 다시 짜지 말고 수정된 라인 주변만 출력하게 하여 시간을 절약합니다.
14. **Plan First 기법:** 코드를 짜기 전 어떻게 구현할지 계획부터 말하게 하고, 승인 후 진행합니다.
15. **도메인 용어 통일:** 모호한 단어 대신 프로젝트에서 사용하는 정확한 변수명/클래스명을 씁니다.
16. **에러 원문 복붙:** 에러 메시지는 임의로 요약하지 말고 스택 트레이스 원문 그대로 제공합니다.
17. **Expected vs Actual:** 의도한 동작과 현재 발생하는 잘못된 동작을 명확히 대조하여 설명합니다.
18. **영어 프롬프트 병행:** 복잡한 알고리즘이나 성능 최적화 질문은 영어로 물어볼 때 더 정확합니다.
