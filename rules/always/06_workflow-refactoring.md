# 개발 워크플로우 및 리팩토링

46. **디버깅 전 원인 분석:** 코드부터 무작정 고치지 말고 "왜 에러가 났는지 원인 3가지를 먼저 추론해"라고 묻습니다.
47. **사이드 이펙트 검증:** 수정된 코드가 다른 모듈(예: 이동과 상호작용)에 미칠 잠재적 영향을 짚어달라고 합니다.
48. **로그 위치 추천:** 에러 추적을 위해 최적의 `Debug.Log` 위치를 설계받습니다.
49. **병목(Bottleneck) 분석:** Update 몬스터 등 성능 이슈 발생 시 코드 내 병목 의심 지점을 찾아달라고 합니다.
50. **셀프 코드 리뷰:** 커밋 전 AI에게 "네가 방금 짠 코드를 시니어 개발자의 시각으로 비판적으로 리뷰해봐"라고 지시합니다.
51. **정규식 테스터 활용:** 복잡한 정규 표현식은 타겟 예시 문자열과 함께 생성 및 테스트를 검증받습니다.
52. **네이밍 추천받기:** 의미가 모호한 변수명/클래스명에 대해 5가지 대안을 제안해 달라고 합니다.
53. **Early Return 리팩토링:** `if-else`가 깊어진 코드를 가독성 좋게 Early Return 패턴으로 즉각 개선시킵니다.
54. **매직 넘버 제거:** 하드코딩된 수치들을 찾아내어 상수로 빼거나 ScriptableObject 데이터로 분리하도록 자동화합니다.
