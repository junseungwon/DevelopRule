# Validator Skill (검증 스킬)

## 📋 스킬 정의

| 속성 | 값 |
|------|-----|
| **스킬명** | validate-spec |
| **역할** | 규칙 명세 품질 및 실행 가능성 검증 상세 실행 |
| **입력** | developer-agent-spec.md |
| **출력** | validation-report.md, recommendations.md |

---

## 📤 출력: validation-report.md

**작성 언어: 한국어** (모든 보고서는 한국어로 작성)

```markdown
# 규칙 명세 검증 보고서

## 1. 검증 요약

| 항목 | 결과 |
|------|------|
| 전체 검증 항목 | 50 |
| 통과 | 42 (84%) |
| 경고 | 5 (10%) |
| 오류 | 3 (6%) |
| 검증 상태 | 조건부 승인 |

## 2. 필수 기준 검증

### 2.1 포맷 검증
- 불필요한 뛰어쓰기 제거 여부
- 아이콘/이모지 사용 금지 여부
- 규칙 길이 50줄 이내 여부

### 2.2 책임 명확성
- 규칙의 책임이 단일하고 명확한가?

### 2.3 발견사항
예: 규칙 R001 - PascalCase 클래스명
- 포맷: 양호
- 책임: 명확
- 자동화: 가능

## 3. 명확성 검증

### 3.1 기준
- 각 규칙의 목표가 단일하고 명확한가?
- 규칙명이 규칙의 내용을 정확히 표현하는가?
- 적용 범위(scope)가 명확한가?
- 조건(condition)이 구체적이고 검증 가능한가?
- 조치(action)가 실행 가능한가?

### 3.2 발견사항
- 명확성 점수: 84%

## 4. 실행 가능성 검증

### 4.1 기준
- 규칙을 정규표현식으로 표현 가능한가?
- 검증에 필요한 도구가 있는가?
- 자동 수정이 가능한가?

### 4.2 발견사항
자동화 가능 규칙: R001-R008 (정규표현식 가능)
부분 자동화 규칙: R010-R015 (추가 도구 필요)
수동 검증 규칙: R020-R025 (수동 검토)

## 5. 문제점 및 권고사항

### Critical (즉시 수정 필요)

R025: 보안 가이드라인 - 정의 불명확
문제: 무엇이 "보안 취약점"인가?
권고:
1. 구체적 취약점 유형 정의
2. 각 취약점별 검증 패턴 작성
3. OWASP Top 10 기준으로 분류

### Major (검증 전 수정 권고)

R010: 에러 처리 패턴 - 적용 범위 불명확
문제: 어느 레이어의 비동기 작업?
권고:
1. 레이어 명시
2. 예외 케이스 정의
3. 에러 핸들링 패턴 구체화

## 6. 통과 기준

### 필수 기준
- 뛰어쓰기/아이콘 없음
- 규칙 길이 50줄 이내
- 규칙 책임 명확성 100%

### 일반 기준
| 항목 | 통과 기준 |
|------|----------|
| 규칙 명확성 | 80% 이상 |
| 실행 가능성 | 60% 이상 |
| 완전성 | 100% |
| 일관성 | 100% |

결론: 필수 기준과 명확성/실행 가능성 기준을 모두 만족하면 규칙 승인
```

## 📤 출력: recommendations.md

**작성 언어: 한국어** (모든 보고서는 한국어로 작성)

```markdown
# 규칙 개선 권고안

## 1. 우선순위별 개선 항목

### P0: 즉시 처리 (개발 전)
- R025: 보안 가이드라인 (정의 명확화)

### P1: 개발 전 처리 권고
- R010-R015: 에러 처리, 로깅, 예외 처리
- 작업량: 2-3시간

### P2: 개발 중/후 처리 가능
- R001-R008: 네이밍, 포맷팅
- R020-R024: 구조 패턴
- 작업량: 개발 중 지속 검증

## 2. 규칙별 개선 템플릿

### R025: 보안 가이드라인

현재:
규칙명: 보안 취약점 방지
범위: 모든 코드
조건: 보안 취약점이 없어야 함
조치: 코드 검토 및 수정

개선안:
규칙명: OWASP 상위 10대 취약점 방지
범위: Data Layer, Business Logic
조건:
  - SQL Injection 방지: 파라미터화된 쿼리 사용
  - XSS 방지: 사용자 입력 sanitization
  - CSRF 방지: 토큰 검증
조치: 자동 검사 + 수동 검토
자동화: 20% (정적 분석)
```

## ⚙️ 검증 실행 방식

입력: developer-agent-spec.md

필수 기준 검증
- 뛰어쓰기/아이콘 제거 확인
- 규칙 길이 50줄 이내 확인
- 책임 명확성 확인

규칙 명세 분석 및 파싱

4가지 검증 기준 적용
- 명확성 검증 (목표/범위/조건/조치)
- 실행 가능성 검증 (자동화 가능성)
- 완전성 검증 (예시/예외 케이스)
- 일관성 검증 (충돌/중복)

문제점 분류 (Critical, Major, Minor)

권고사항 작성 (한국어로 작성)

출력: validation-report.md + recommendations.md (모두 한국어)
